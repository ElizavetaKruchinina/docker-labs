
# Ответы на вопросы по лабораторной работе

## 1. Использование `LAB_LOGIN` и `LAB_TOKEN` и связь с `/proof`

В Dockerfile `LAB_LOGIN` и `LAB_TOKEN` используются только как аргументы сборки: они существуют исключительно на этапе `docker build` и применяются для заполнения меток образа (`LABEL`). 

Приложение читает данные из переменных окружения контейнера. При обычном запуске (`docker run` без флага `-e`) этих переменных в окружении нет, поэтому приложение получает `None` (или пустые значения).

Эндпоинт `/proof` нужен, чтобы показать полученные логин и токен. Так как при обычном запуске данные отсутствуют, `/proof` вернёт пустой результат (или ошибку, как показано на скриншоте).

## 2. Уменьшение размера образа

Уменьшение размера достигается за счёт следующих приёмов:
- **Использование Alpine Linux** вместо полноценной ОС. В качестве базового образа выбран `python:3.12-alpine`, который значительно компактнее стандартного `python:3.12`.
- **Установка зависимостей с флагом `--no-cache-dir`**: флаг `pip install --no-cache-dir` отключает создание кэша пакетов, поэтому в образ не попадают временные файлы pip.
- **Копирование только нужного**: в финальный образ копируется только код приложения (`COPY app/ ./app/`) и установленные пакеты, без лишних директорий и файлов.

### Назначение `--worker-tmp-dir /dev/shm`

Флаг `--worker-tmp-dir /dev/shm` указывает Gunicorn хранить временные файлы (heartbeat-файлы воркеров) не в стандартной директории `/tmp`, а в `/dev/shm`. 

`/dev/shm` — это `tmpfs` (файловая система в оперативной памяти), следовательно, операции чтения/записи в ней происходят значительно быстрее, что предотвращает зависания воркеров из-за медленного дискового ввода-вывода.
